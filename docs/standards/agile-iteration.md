# 敏捷迭代与即开发即使用标准 v0.1

## 1. 核心原则

OpenStock AI 采用敏捷迭代方式开发。

项目要求：

* 即开发，即使用
* 小步提交
* 每个版本可运行
* 每个功能可验证
* 每次迭代有明确版本号
* 每次迭代同步 docs
* 每次迭代保留测试证据

本系统仅用于投资研究辅助，不构成任何投资建议。

## 2. 迭代单位

每一轮迭代必须有明确目标。

推荐迭代粒度：

* 1 个可用功能
* 1 个可验证 API
* 1 个 Agent 能力
* 1 个数据源适配器
* 1 个页面或用户流程
* 1 个文档标准升级

禁止一次迭代混入大量无关改动。

## 3. 迭代流程

```text
定义迭代目标
  -> 创建 feature/* 或 docs/* 分支
  -> 更新需求或设计文档
  -> 实现最小可用功能
  -> 添加测试
  -> 本地运行验证
  -> 更新 CHANGELOG
  -> 提交 PR
  -> 合并到 develop
  -> 需要发布时打 tag
```

## 4. 即开发即使用要求

每个合并到 `develop` 的功能必须满足：

* 可以本地启动或通过测试验证
* README 或 docs 说明如何使用
* 不依赖未提交的本地文件
* 不依赖硬编码 API Key
* 失败时有清晰错误信息
* 投资相关输出包含风险提示

## 5. 版本节奏

第一阶段使用 `0.x` 版本。

推荐节奏：

```text
0.1.x  项目治理、需求、架构、基础工程
0.2.x  后端 API、配置、数据库、audit_logs
0.3.x  数据源接入
0.4.x  AI Agent 与模型统一接口
0.5.x  股票评分与推荐等级
0.6.x  前端可用页面
0.7.x  回测与模拟组合
0.8.x  端到端 MVP
0.9.x  发布候选和稳定性修复
1.0.0  第一个稳定可用版本
```

## 6. 每轮迭代验收清单

每轮迭代完成前必须确认：

* 功能可以运行或测试通过
* 新增代码有测试
* 新增模块有 docs
* API 有错误处理
* AI 输出有审计记录设计
* 投资结论有风险提示
* CHANGELOG 已更新
* 没有敏感信息进入仓库

## 7. 开发状态标记

功能状态必须明确：

```text
planned      已规划，尚未开发
in_progress  开发中
usable       可本地使用
verified     已测试验证
released     已发布版本
deprecated   已废弃
```

docs 中描述功能时必须避免把 `planned` 或 `in_progress` 写成 `released`。
